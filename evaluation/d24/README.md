## 人による確認

上記の現在版の確認HTMLをローカルブラウザーで開き、各ケースの依頼文・初期状態・
期待する変化を見ます。10件ずつ表示し、未確認だけの絞り込みもできます。
各ケースを「この期待動作でよい」「修正が必要」で記録してください。
確認者名を入力して「確認記録をダウンロード」を押すとJSONを保存できます。
未確認が残っていても出力できます。ブラウザー内の途中保存は補助で、JSONを保存してください。

開発用の記録はこの作業に返せます。**最終評価用のメモや文章を実装担当の会話に
貼らないでください。** その記録は同じ隔離フォルダーに保存し、ファイルの場所だけを
伝えてください。別の評価担当が内容を確認します。人が未確認のものは未承認のままです。

承認はケース全体のハッシュに結び付けます。文章・状態・正解を変えたら再確認が必要です。
AIの点検と人の承認の両方があるケースだけが、後の最終集計に参加できます。
確認用画面は自分のPC内で動き、外部通信・モデル呼び出し・製品設定の変更を行いません。
署名付き認証システムではなく、確認者が記録を提出する運用です。

## 作業用コマンド（backendから）

```powershell
python -m uv run python -m scripts.evaluation_cases validate --cases ../evaluation/d24/development.jsonl --ai ../evaluation/d24/development.independent-ai-review.json
python -m uv run python -m scripts.evaluation_cases review --cases ../evaluation/d24/development.jsonl --output <新しい確認HTMLの絶対パス> --pending-output <新しい未承認台帳の絶対パス>
python -m uv run python -m scripts.evaluation_cases eligible --cases <ケースJSONL> --human <本人が返した確認JSON> --ai <独立AI確認JSON> --output <新しい集計対象一覧JSON>
```

全出力は新規作成専用で、確認記録を上書きしません。`eligible` は承認済みが0件なら
エラーで止まり、成績も空の集計も出しません。承認済みの一部だけを使う場合も、全件数・
採用件数・除外件数を残します。既存プローブが自動的にこの承認機構を使うわけではありません。
D25以後のランナーは、この対象一覧とケースハッシュを検証してから集計に使ってください。

## 範囲と扱い

D24は素材と正解の整備です。モデル推論、プロンプト改善、検索追加、動画再生成は行いません。
ガードにより誤保存を防げたことと、依頼どおり完了したことは別の指標です。
質問不要の明確な依頼まで断れば、そのケースは完了失敗です。

隔離は担当・フォルダー・作業手順によるものです。OS権限で別担当からアクセスを禁止する
仕組みではありません。開発中に最終評価の本文や失敗例を見た場合は、露出した元要求群を
開発用へ移し、未見の性能を測るには別の群を用意します。最終評価を見てから閾値や期待値を
都合よく変更しません。D36で評価条件を固定する前に、ラベル承認の残りを確認します。
