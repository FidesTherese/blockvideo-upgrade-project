# D13：生成中の設定変更と成果物履歴の方針

確認日：2026-09-19。以下は実装前の方針決定記録。現在はD13の履歴保存・版別表示を実装・検証済み。
現状と証拠は [D12–D15実装報告](work-report-12-15.md) を参照。

## 利用者が選択した方針

1. **生成中は設定変更不可を維持する。**
   現行のDEC-04を維持する。生成待ち・生成中の対象プロジェクトへの
   設定変更は保存せず、完了またはキャンセル完了後に変更できるようにする。
   実行中の設定へ後から変更を混ぜる方式にはしない。
2. **成功した動画をすべて履歴として残す。**
   容量が増えることを含めて選択された。直前の1件だけへの制限や、
   新しい成功動画による過去動画の自動上書き・自動間引きは行わない。

この確認は上記2点の製品方針であり、D13のコード実装・実動作確認の完了ではない。
D12の依存工程計画を実装した後、D13のジョブ・成果物との対応付けに使用する。

## 表示への落とし込み

以下は選択された方針に沿う実装時の表示案。revisionは設定の版番号を意味する。
利用者向けには「設定の版」と表記し、必要なら詳細に番号を表示する。

| 状態 | 表示案 | 動画の扱い |
|---|---|---|
| 生成待ち・生成中 | 「生成中のため設定を変更できません」＋工程・進捗 | 前回の動画を表示する場合は「前回の完成動画」と明示 |
| 設定だけ変更して保存済み | 「設定は保存済み・動画には未反映」 | 以前の設定で作った動画は「旧版」と表示 |
| 現在の設定・入力に対応する生成が成功 | 「最新設定の動画が完成しました」 | 検証済みの成果物を現在版として表示 |
| 旧版の動画を閲覧 | 「旧版」＋生成日時・設定の版 | 現在版と分けて再生・ダウンロードできる履歴を用意 |
| 再生成が失敗・キャンセル | 失敗／キャンセル状態を表示 | 以前の成功動画の履歴を保持 |

キャンセルボタンを押した直後ではなく、ジョブが停止したことを確認してから
設定変更を可能にする。旧版を再生しただけで現在の設定を巻き戻した扱いにはしない。

## D13の実装に引き継ぐ要件

- ジョブごとに設定revisionと入力・設定snapshot（または等価な識別情報）を保存する。
- 成功動画を生成実行ごとの保存先で保持し、同じ `output/video.mp4` への上書きだけで管理しない。
- 同じrevisionでも明示的に新しく生成した成功結果は履歴に記録する。
  同じ要求IDの再送では、新しいジョブや履歴を増やさない。
- 現在版を指す参照と、履歴の成果物を分ける。完成時にrevision・参照入力・
  実ファイルを検査し、古い結果が後着しても現在版へ昇格させない。
- 失敗・途中ファイルを「成功動画」の履歴に含めない。履歴の実ファイルが
  欠損していたら、その事実を表示し、パスが記録されているだけで成功扱いしない。
- 今回「全件保持」と確認した対象は成功した完成動画。
  中間画像・音声・作業ファイルの全世代保存までは決定していない。

## 方針決定時のコードを確認した結果（実装前の記録）

- `backend/app/api/utils.py` と操作コアのreadinessが生成中の変更を拒否する。
  PATCHはHTTP 409、操作APIは `project_busy` を返す。フロントエンドには
  既存プロジェクト設定を編集する専用フォームがまだない。
- `frontend/src/pages/ProjectDetailPage.tsx` は `output_video_path` があれば
  「完成動画」を表示する。現在設定との一致や旧版かどうかの表示はない。
- `backend/app/services/invalidation.py` は設定変更時に関係工程を未生成へ戻すが、
  既存の完成動画を削除しない。旧動画を最新版と見分ける表示は別途必要。
- `backend/app/services/pipeline.py` は `video.pending.mp4` の結合に成功すると
  `output/video.mp4` を置き換える。版別の動画履歴は現在保存していない。
- ジョブ履歴やD11の要求記録は存在するが、過去のMP4ファイルの保管とは別である。

確認時に関連する既存テスト13件が成功した。これは現行の変更拒否・設定保存・
部分再生成の確認であり、未実装のD13履歴機能を検証したものではない。
ブラウザでの実画面確認はこの確認作業には含めていない。
