- `app/retrieval/`：E5のローカルONNX実行、モデル・tokenizerの検証、操作単位の順位付け。

## 採用した動作と境界

最初の5候補で質問・未対応・不正な構造化出力になった場合、8候補へ一度だけ拡張し、
さらに必要なら同じアプリ・対応能力・操作版の全候補へ一度だけ切り替える。
全候補が32件を超える場合や切替を無効にした場合は質問で停止する。
候補の選択には検索順位を使い、モデルへ渡す定義とschemaはID・版の固定順にする。

各狭い段階は会話モデル1回、全候補の段階だけ出力修正を1回許す。
合計は埋め込み1回・会話モデル最大4回・候補拡張1回・全候補への切替1回・全体180秒。
接続断は候補不足として再試行しない。途中の提案は実行しない。

候補0件は質問、古い索引や正本との不一致はエラーで止まる。埋め込みだけが失敗した場合は
検証済みの同じ範囲の全操作へ切り替えられる。「未対応」は全操作を確認した場合だけ返す。
検索前後の正本整合性を検査し、検索範囲を越える操作や生成を許可しない。
候補は実行可能性で間引かない。readinessの候補への注釈はD28の範囲。

画面には「最初の候補では十分に判断できなかったため、確認する操作の範囲を広げました。」
と表示する。詳細欄の類似度は小数で、正解確率ではないと説明する。
バイト数はmessages・schema・応答内容のUTF-8サイズであり、トークン数・料金・HTTP全体の通信量ではない。
