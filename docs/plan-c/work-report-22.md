## 実装した動作

利用者に確認し、「設定をまとめて保存し、生成だけ確認する」を採用した。
字幕サイズ、読み方、話速などを一つの依頼で受け取り、全値を検証して一括保存する。
一部だけ不明・不正な場合は部分保存しない。生成の希望が含まれる場合は、保存した差分と版を示して開始を確認する。
生成を取り下げても設定は残る。保存後に訂正があれば現在値を基準に新しい版で保存し、古い確認は無効になる。

- `project.settings.update` v2: `settings` と `subtitle_font_size_delta`。
  相対値は要求記録の照会、revision検査の後、同一の書込トランザクション内で解決する。
  絶対サイズと増減量の併記、空変更、範囲外、不正な読み方・アクセントを拒否する。
  v1と同じ専門検証・設定保存・履歴・工程無効化を再利用する。8 ID・9版の定義。
- `generate_after_save`: 解釈結果の生成希望。実行権限ではない。
  設定の記録から別IDと確定revisionを持つ生成要求を作り、専用確認トークンで開始する。
  設定結果と生成結果を別に表示し、保存・生成それぞれの応答消失を既存receiptで復元する。
  設定保存の確認を再送しても、次段階の生成確認にはならない。
- 複数変更による影響工程を既存plannerで一つのジョブへ統合する。
  再送・再読込・同時確認で余分なジョブや版を作らない。
- 解釈の修復は追加一回、合計最大二回・120秒。
  不正JSON/返答形式だけが対象。引数の値不足・候補外・接続失敗・拒否・途中応答は修復で推測しない。
  元の入力と固定エラーコードだけを渡し、不正な返答本文は再投入しない。
  試行数と修復コードを永続化し、同じ要求の再送で予算をリセットしない。
- 対話には設定保存済みの印を渡す。生成確認待ちを「設定も未保存」と解釈させない。
  コアやモデルから言語オーケストレーションへの逆依存は追加していない。
