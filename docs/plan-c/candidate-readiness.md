# D28 候補の実行条件

検索は「どの操作が文章の意味に近いか」を扱い、実行条件は「その操作を今できるか」を扱う。
例えば生成中に「話速を1.2倍にして」と頼んだ場合、意味が合うのは設定変更である。
現在は変更できなくても候補から消さず、生成中という理由をモデルと画面へ渡す。
生成停止・再試行・状態照会を代わりに実行する指示にはしない。

## 候補の段階では、値の検証がまだ終わっていない

候補の状態は引数を解釈する前に作る。次の区別を設けた。

| 表示 | 判定できたこと | まだ保証しないこと |
|---|---|---|
| 生成中のため変更できません | 共通コアの対象・実行中ジョブ検査で編集禁止 | 完了後の自動実行や予約 |
| 値・参照を確認してから判定します | 対象に既知の状態制約がない | 値の範囲、ジョブ番号、戻す版、生成方法の妥当性 |
| 対象・状態の制約なし（暫定） | 状態照会のような引数なし操作の対象・状態検査 | 後で状態が変わらないこと、実行権限 |
| 対象が見つかりません等 | 対象や操作版を使えない | 別対象・別操作への自動置換 |

`arguments_unchecked`は「入力文に値が欠けている」という断定ではない。
候補の観測時点では、まだ確定した引数を検証していないという意味である。
実際の文章の値が明確ならモデルが抽出し、共通コアが検証する。不足なら質問する。

型は`CandidateReadiness`と`CandidateReadinessSnapshot`。
各候補はID・版、`phase: candidate_preview`、`arguments_checked: false`、状態、理由、
未確認項目、対象、設定revisionを持つ。snapshotには観測時刻を持たせる。
ジョブの開始・終了だけでは設定revisionが変わらないため、revisionだけで鮮度を判定しない。

## どこで状態を調べるか

`operations.candidate_readiness.candidate_snapshot`が既存の`evaluate_readiness`を使う。
実行用の架空の引数や要求IDを作って呼ぶのではなく、対象と状態で判断できる範囲に限定する。
DBを扱うlanguage側が新しい読み取りsnapshotを供給し、検索・解釈層へDBやexecutorは渡さない。
5候補、8候補、全候補の各段階で状態を取り直し、呼出しの前後で読み取りtransactionを閉じる。

readinessを理由に検索順位や候補集合を変えない。候補拡張でもblockedを残す。
モデルへ渡す注釈は提示候補の正確なID・版・対象だけに対応し、欠落・重複・別対象の注釈を拒否する。
類似度を実行許可に変換しない。

確定した提案は、従来の値・参照ガード、readiness、revision、確認、writer transaction内の再検査を通る。
モデル応答の途中や確認ボタンを押す前に生成が始まった場合も、最新のコア検査で拒否される。
候補の注釈があるからといって検査を省略する経路はない。

## 画面の記録と現在の状態

結果カードの「候補の実行条件」は、依頼の判断時点の観測を初期表示する。
「候補の状態を更新」は`GET /api/language/requests/{request_id}/candidate-readiness`だけを呼ぶ。
このAPIは記録された候補の現在の条件を返し、モデル・索引・操作の実行を呼ばない。
元の拒否結果、診断、要求IDを変更しない。

生成が終わった後に更新すると、理由が「生成中」から「値・参照を確認してから判定」に変わる。
元のカードは「この依頼は実行しませんでした」「依頼の判断時点の理由」として残る。
設定を変えるには新しく依頼する。同じIDの再送は元の拒否結果を返す。
現在の状態を取得できなければ、前回の観測を表示していることを明示する。

## 設定と実験用Hard Filter

`LANGUAGE_RETRIEVAL_INDEX`未設定なら従来のAll Tools。
索引を設定した経路では`LANGUAGE_RETRIEVAL_READINESS=true`（既定）で注釈を付ける。
`false`でD27の注釈なし検索を使える。設定ファイルの`.env`は今回変更していない。

`evaluation.readiness_filter.hard_filter_candidates`は比較用の純粋関数である。
入力候補とsnapshotを一致検査し、既知のblocked/unsupportedだけを除く。
引数が未検査という理由だけでは除かない。結果0件も許す。
実験側は返されたID・版をfallbackを含む全検索範囲として渡し、候補を勝手に復活させない。
この関数は製品側からimportしない。設定画面やAPIでHard Filterを選ぶこともできない。
D29で方式を同条件にそろえる共通ランナーを作る。今回、比較方式の優劣は結論付けない。
