## 決定と実装

ユーザーは「既存のNomicで索引の生成・更新を検証し、日本語の検索精度とモデル選定はD27で確認する」を選択。
会話用Ternary Bonsaiとは別に、既存のNomic Embed Text v1.5 Q4_K_Mを使用した。
ローカルJSONファイルへ保存し、少数操作に大きな検索基盤は追加しなかった。追加依存・ダウンロードなし。

操作定義の説明・例文・入力schemaから、9件の版付き定義に対応する90文書を生成する。
`search_scope.json` はアプリ・対応能力・正確な操作版の対応だけを追加し、正本と一対一に照合する。
生成中などの動的状態は索引に入れず、readinessで候補を消す処理とも分離した。

manifestは元の2ファイル、定義内容、文書、ベクトル、モデル重みのハッシュと版を持つ。
埋め込みには指定された文書用接頭辞を付け、768次元の有限なベクトルをL2正規化する。
モデルID、件数、行番号、次元を検査し、応答本文をエラーへ転記しない。

bundleを保存してからmanifestを原子的に置換する。失敗・再構築で過去bundleを削除しない。
読み手は正本から文書を再生成して照合するので、索引側だけで不明なID・版や別の説明へ置き換えても拒否される。
モデル/インタープリター/通常APIには索引更新コマンドを渡していない。

詳細・根拠・コマンドは [operation-index.md](operation-index.md)。
