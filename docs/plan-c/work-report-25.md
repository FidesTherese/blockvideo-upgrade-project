## 変更

- 操作判断、結果照会、生成受付の待ち時間を動画生成の進捗とは分けた。利用者の指定どおり30秒で遅延案内を出し、案内だけでは取消・再送しない。再読み込みはGET照会、応答不明時は元の要求を保持、生成は明示確認を維持する。
- 接続失敗と指定値・出力のエラーで案内を分け、確定したエラーから新しい依頼へ戻れるようにした。
- 応答JSONに開始時刻、候補ID/版、判断・検証時間、実行受付時間、後続生成受付時間、保存前チェックの理由を追加。HTTP失敗は本文を記録せず番号だけ保持。旧レコードの未記録時間は0とせず、クラッシュ後は実行記録を正として復旧する。
- 「要求の記録」に要求/実行ID、版、ジョブ、抽出値、確定値、時間、拒否理由を表示。
- 操作ログは許可した項目だけ。IDをプロセス固有鍵のHMACへ置換し、依頼文・台本・名称・読み方・モデル返答・確認トークン・未知の引数名を出さない。アクセスログの要求IDとクエリも除去。これは仮名化であり、再起動をまたぐ同一仮名は保証しない。
- 開発プローブは人と独立AIの両方が承認したケースだけを使用。候補・出力形式・プロンプト・corpusのハッシュ、試行数、時間を記録する。実アプリの全効果を採点するD29のランナーとは別である。
- 否定、量、話速、複数設定、短い回答の規則を調整。設定JSON Schemaは意味が等しい3通りの項目順をモデルに提示する。登録操作・型・値域・必須項目・コアの検査は変えない。

項目順の互換性はローカル実測で判断した。背景として[llama.cppのJSON Schema変換](https://github.com/ggml-org/llama.cpp/blob/master/common/json-schema-to-grammar.cpp)と[順序に関するテスト](https://github.com/ggml-org/llama.cpp/blob/master/tests/test-json-schema-to-grammar.cpp)を参照した。今回のLM Studio内部の実装原因まで確定したという意味ではない。
