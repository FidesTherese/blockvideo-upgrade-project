## 実装

`evaluation.comparison` がB0、B1、B2、P1、B0+を選び、同じ言語処理と実行コアへ接続する。
通常のアプリの既定動作・`.env`・操作カタログ・共通ガードは変更していない。
実験用CLIの `--modes` で切り替える。詳細は `comparison-modes.md`。

- B0は全操作、B1は意味検索、B2は確定的な実行不能候補を除外して検索＋状態説明、
  P1はB1の候補を保持＋状態説明、B0+は全操作＋状態説明。
- 全方式で質問・非実行を許す。B2は引数未検査の候補を残し、fallbackでも除外候補を戻さない。
- 180秒・最大4チャット・全候補でJSON/出力形式の修復1回という上限を共通化。
  全操作方式は通常1回／修復込み2回。検索方式は候補拡張分を含む最大4回。
- 同じraw状態・モデル設定・出力schema生成器・parser・ガード・最終readiness・
  確認・revision・transaction・登録済みhandlerを使う。
- 試行ごとに独立DBとmediaフォルダーを作り、初期状態を復元する。
  1プロセス内の並行試行は拒否。通常DBや媒体を比較実験に使わない。
- 承認ゲート、manifest、実際の合成prompt/schema/応答、候補・順位・注釈、
  実行前後のDB差分、再送、ソース・索引・承認ファイルのハッシュを保存する。

製品側の変更は候補解釈器の構造的インターフェース、全操作用traceの識別と表示型の追加。
